PARTE 1

Uma visão geral

O que são bases de dados NoSQL?

NoSQL significa habitualmente Not Only SQL. O nome reúne diferentes famílias de bases de dados que não organizam obrigatoriamente toda a informação em tabelas relacionadas nem usam SQL como linguagem principal.

Não existe um único “modelo NoSQL”. Há bases documentais, chave-valor, colunares e orientadas a grafos. Nesta aula interessa sobretudo perceber três razões que contribuíram para a sua popularidade: flexibilidade da estrutura, distribuição dos dados e tolerância a falhas.

1.1

Estrutura dos dados

Flexibilidade

Numa tabela relacional definimos antecipadamente colunas, tipos de dados, chaves e restrições. Todos os registos respeitam essa estrutura. Isto favorece a coerência, mas torna mais exigentes algumas alterações ao modelo.

Numa base documental, cada documento pode ter campos diferentes. A aplicação consegue guardar uma nova estrutura sem alterar previamente todas as outras ocorrências.

Essa liberdade tem um custo: a base de dados não garante automaticamente que todos os documentos tenham os campos esperados ou os valores corretos. A aplicação e as regras de validação passam a ter um papel importante.

1.2

Dados distribuídos

Tolerância a falhas

Os dados podem ser distribuídos e replicados por vários servidores. Se um servidor falhar, outro pode continuar a responder. A replicação também permite aproximar cópias dos utilizadores e distribuir o trabalho.

Nesta aula não vamos configurar réplicas. Estas imagens explicam a motivação. A parte prática usa uma única instância de MongoDB.
PARTE 2

Primeiros passos

MongoDB numa versão muito leve

O MongoDB guarda documentos, semelhantes a objetos JSON, dentro de coleções. As coleções pertencem a uma base de dados.

base de dadoscontémcoleçõescontêmdocumentos

Partimos do princípio de que o MongoDB já está instalado através do guião Docker disponibilizado aos alunos.

Abrir um terminal no contentor

docker compose exec mongo bash

docker compose exec manda executar um comando num serviço que já está a correr. O primeiro mongo não é uma palavra reservada: é o nome atribuído ao serviço ou contentor no ficheiro Compose. bash abre uma linha de comandos dentro desse contentor.

Entrar na consola do MongoDB

mongosh

mongosh é o cliente: a aplicação através da qual escrevemos comandos e recebemos resultados. O servidor é o processo mongod, que o Docker Compose já iniciou dentro do contentor quando executámos docker compose up -d. Ao escrevermos mongosh, abrimos o cliente e este liga-se ao servidor que já estava à espera de ligações.

$ docker compose exec mongo bashroot@contentor:/# mongoshtest>
2.1

Criar ao inserir

A primeira base, coleção e documento

No modelo relacional começaríamos por criar a base de dados, criar a tabela, escolher as colunas e tipos, definir as chaves e só depois inserir uma linha. Aqui começamos diretamente pelo documento.

use faculdade

db.aluno.insertOne({
  numero: 105514,
  nome: "Ana Silva",
  curso: "LEI"
})
Resultado simplificado
{ acknowledged: true, insertedId: ObjectId("...") }

use faculdade seleciona o nome da base de dados. O MongoDB só a cria efetivamente quando guardamos o primeiro documento. db.aluno.insertOne(...) cria a coleção aluno, se ainda não existir, e insere o documento.

Confirmar o que foi criado

show dbs
show collections
db.aluno.find()
Resultado
[{
  _id: ObjectId("..."),
  numero: 105514,
  nome: "Ana Silva",
  curso: "LEI"
}]

O campo _id identifica unicamente o documento. Como não o fornecemos, o MongoDB criou-o automaticamente.

2.2

Flexibilidade e risco

Um erro pode criar outra coleção

Agora queremos inserir outro aluno, mas escrevemos por engano o nome da coleção no plural:

db.alunos.insertOne({
  numero: 122715,
  nome: "Bruno Costa",
  curso: "LIGE"
})
show collections
Resultado
aluno
alunos

O MongoDB não sabe que foi um engano. Criou uma nova coleção chamada alunos. A flexibilidade torna algumas tarefas simples, mas também exige atenção aos nomes.

Um novo documento pode ter outros campos

db.aluno.insertOne({
  numero: 123013,
  nome: "Carla Rocha",
  curso: "LEI",
  email: "carla@example.org",
  interesses: ["dados", "programação"]
})

O primeiro documento continua sem email e interesses. Não foi necessário alterar previamente a coleção. Esta é uma diferença essencial em relação a uma tabela relacional tradicional.

Mais simples não significa sem regras. Em aplicações reais podemos definir validações para impedir nomes errados, campos obrigatórios ou tipos inadequados.
2.3

A analogia com SELECT

Consultar documentos com find

find desempenha um papel semelhante ao SELECT. O primeiro objeto indica o filtro, como o WHERE. O segundo objeto indica os campos a mostrar ou esconder.

SQL
SELECT *
FROM aluno
WHERE curso = 'LEI';
MongoDB
db.aluno.find({
  curso: "LEI"
})

AND

Campos escritos no mesmo filtro são ligados por AND:

db.aluno.find({
  curso: "LEI",
  numero: { $gt: 110000 }
})

OR

db.aluno.find({
  $or: [
    { curso: "LEI" },
    { curso: "LIGE" }
  ]
})

AND e OR na mesma consulta

Procurar alunos de LIGE ou alunos de LEI com número superior a 110000:

db.aluno.find({
  $or: [
    { curso: "LIGE" },
    {
      $and: [
        { curso: "LEI" },
        { numero: { $gt: 110000 } }
      ]
    }
  ]
})

NOT

Excluir os documentos cujo curso é LIGE:

db.aluno.find({
  curso: { $not: { $eq: "LIGE" } }
})

Numa desigualdade simples também podemos escrever { curso: { $ne: "LIGE" } }.

Mostrar apenas alguns campos

db.aluno.find(
  { curso: "LEI" },
  { nome: 1, curso: 1, _id: 0 }
)
Resultado
{ nome: "Ana Silva", curso: "LEI" }
{ nome: "Carla Rocha", curso: "LEI" }

Esconder campos

db.aluno.find(
  {},
  { email: 0, interesses: 0 }
)

Na projeção usamos normalmente inclusões (1) ou exclusões (0), mas não misturamos as duas. _id é a exceção e pode ser escondido numa projeção de inclusão.

Ordenar os resultados

db.aluno.find({}).sort({ curso: 1, nome: 1 })

O resultado é ordenado primeiro por curso e, dentro de cada curso, por nome. O valor 1 significa ordem crescente; -1 significa ordem decrescente.

2.4

Agrupar e guardar

Agregação com $group e $merge

Uma agregação é uma sequência de etapas. Cada etapa recebe os documentos produzidos pela anterior. Para contar alunos por curso, agrupamos pelo campo curso e somamos uma unidade por documento.

db.aluno.aggregate([
  {
    $group: {
      _id: "$curso",
      total: { $sum: 1 }
    }
  },
  { $sort: { total: -1 } }
])
Resultado possível
{ _id: "LEI",  total: 2 }
{ _id: "LIGE", total: 1 }

Aqui, _id representa o valor usado para formar cada grupo. $sum: 1 acrescenta um por cada documento do grupo. $sort ordena do maior para o menor.

Guardar o resultado noutra coleção

db.aluno.aggregate([
  {
    $group: {
      _id: "$curso",
      total: { $sum: 1 }
    }
  },
  {
    $merge: {
      into: "resumo_cursos",
      on: "_id",
      whenMatched: "replace",
      whenNotMatched: "insert"
    }
  }
])

$merge grava o resultado na coleção resumo_cursos. Se um curso já existir, substitui o respetivo resumo; se ainda não existir, insere-o.

db.resumo_cursos.find()
Resultado
{ _id: "LEI",  total: 2 }
{ _id: "LIGE", total: 1 }

O equivalente a WHERE e HAVING

Queremos guardar os países que têm mais de 100 filmes com uma duração mínima de 90 minutos. Neste exemplo, $match aparece duas vezes porque está a filtrar resultados diferentes em momentos diferentes da pipeline.

db.movies.aggregate([
  { $match: { duration: { $gte: 90 } } },
  {
    $group: {
      _id: "$country",
      TotalMovies: { $sum: 1 }
    }
  },
  { $match: { TotalMovies: { $gt: 100 } } },
  {
    $project: {
      _id: 0,
      Country: "$_id",
      TotalMovies: 1
    }
  },
  { $merge: "countries_100longmovies" }
])
1.º $matchWHEREFiltra documentos de movies antes do agrupamento: apenas filmes com pelo menos 90 minutos.
$groupGROUP BYCria um grupo por país e calcula TotalMovies.
2.º $matchHAVINGFiltra os grupos já calculados: apenas países com mais de 100 filmes.
$projectSELECTEscolhe os campos apresentados e muda _id para Country.
$mergeGuardarGrava o resultado na coleção countries_100longmovies.

A segunda utilização de $match já não vê os filmes originais. Recebe apenas os documentos produzidos por $group, que têm campos como _id e TotalMovies.

Consulta SQL equivalente

SELECT country, COUNT(*) AS TotalMovies
FROM movies
WHERE duration >= 90
GROUP BY country
HAVING COUNT(*) > 100;

O essencial

O que deve ficar desta aula

  1. Uma base documental guarda documentos em coleções.
  2. O MongoDB pode criar a base e a coleção no primeiro insertOne.
  3. Documentos da mesma coleção podem ter campos diferentes.
  4. find filtra documentos e escolhe os campos apresentados.
  5. aggregate transforma e agrupa documentos; $merge pode guardar o resultado.
