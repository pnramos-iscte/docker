1970

De onde veio o SQL?

O modelo relacional e a linguagem SQL nasceram no mesmo programa de investigação da IBM, mas não exatamente ao mesmo tempo nem pelas mesmas pessoas.

1970

O modelo relacional

Edgar F. Codd publicou o modelo relacional: dados organizados em relações e operações com fundamento matemático.

1974

SEQUEL, antecessor do SQL

Donald Chamberlin e Raymond Boyce apresentaram a linguagem SEQUEL para consultar bases de dados relacionais. O nome evoluiu depois para SQL.

DeclarativaDizemos o que queremos obter. O SGBD escolhe como encontrar os dados.
Base matemáticaAs operações inspiram-se na álgebra e no cálculo relacionais, ligados à teoria dos conjuntos.
Para dados relacionaisSQL nasceu para operar sobre relações. Muitos produtos alargaram a linguagem a outros tipos de dados.
Standard comumA família ISO/IEC 9075 define SQL. MySQL, PostgreSQL, SQL Server e Oracle partilham o núcleo, mas têm extensões e diferenças.
Não é compilada como CO SGBD recebe cada instrução, analisa-a, cria um plano de execução e executa-o. Algumas instruções podem ser preparadas e reutilizadas.
Formatação livreEspaços e mudanças de linha quase nunca mudam o significado. As palavras reservadas não precisam de maiúsculas, embora as usemos para ler melhor.
A ideia essencial: SELECT nome FROM utilizador WHERE reputacao > 60 descreve o resultado. Não manda abrir um ficheiro, percorrer um índice ou comparar linhas numa ordem concreta. O otimizador do SGBD decide esse percurso.

Fontes históricas: artigo de Codd, 1970; artigo SEQUEL de Chamberlin e Boyce, 1974. Standard: ISO, modelo da linguagem SQL.

01

A primeira consulta

SELECT indica as colunas que quer ver. FROM indica a tabela onde os dados estão.

SELECT nome, email
FROM utilizador;

Leia em linguagem corrente

“Para cada linha da tabela utilizador, mostra o valor que está nas colunas nome e email.”

Conceptualmente, o FROM produz linhas e o SELECT calcula o que aparece à frente para cada uma. O SGBD pode executar a consulta de outra forma mais eficiente.

O asterisco

* significa “todas as colunas”. É útil para explorar uma tabela pequena. Em consultas reais, prefira indicar as colunas necessárias.

02

Valores distintos e funções de agregação

Uma coluna pode repetir valores. DISTINCT elimina repetições do resultado. Uma função de agregação resume várias linhas num único valor.

SELECT estado
FROM utilizador;

Primeiro, veja as repetições

A consulta continua a devolver uma linha por cada linha da tabela. Como cinco utilizadores estão ativos, a palavra ativo aparece cinco vezes.

Resultado
estado
ativo
ativo
inativo
ativo
ativo
ativo
SELECT DISTINCT estado
FROM utilizador;

Agora, apenas valores diferentes

DISTINCT compara as linhas produzidas pelo SELECT e conserva apenas uma ocorrência de cada valor. Não altera os dados guardados.

Resultado
estado
ativo
inativo
SELECT COUNT(*) AS total
FROM utilizador;

COUNT muda a granularidade

Sem funções de agregação, o SELECT tende a produzir uma linha por linha de entrada. COUNT(*) agrega o conjunto inteiro e devolve uma única linha, desde que não exista GROUP BY.

COUNT(pais_id) contaria apenas os cinco valores não nulos.

Resultado: seis linhas resumidas numa
total
6
SELECT
  SUM(reputacao) AS soma,
  MIN(reputacao) AS minimo,
  MAX(reputacao) AS maximo,
  AVG(reputacao) AS media,
  STDDEV_POP(reputacao) AS desvio
FROM utilizador;

Outras funções de agregação

SUM soma, MIN e MAX encontram extremos e AVG calcula a média. Em MySQL, STDDEV_POP calcula o desvio padrão populacional e STDDEV_SAMP o desvio padrão amostral.

Tal como COUNT, estas funções ignoram valores NULL na coluna.

Resultado
somaminimomaximomediadesvio
399389166,5017,75
Atenção: SELECT DISTINCT estado, pais_id elimina pares repetidos. Não calcula separadamente os valores distintos de cada coluna.
03

Filtrar linhas com WHERE

WHERE define uma condição. Só as linhas para as quais a condição é verdadeira chegam ao resultado.

= igual
<> diferente
>   >=   <   <= comparações
AND / OR / NOT combinar condições
IN (...) pertence a uma lista
BETWEEN ... AND ... intervalo inclusivo
LIKE compara com um padrão
IS NULL procura ausência de valor
SELECT nome, reputacao
FROM utilizador
WHERE estado = 'ativo'
  AND reputacao >= 60;

Texto entre plicas

Valores de texto e datas escrevem-se entre plicas. Números não precisam de plicas. As duas condições têm de ser verdadeiras porque usamos AND.

Resultado
nomereputacao
Ana Costa82
Fábio Alves74
SELECT nome
FROM utilizador
WHERE nome LIKE 'A%';

Padrões com LIKE

% representa zero ou mais caracteres. _ representa exatamente um carácter. O exemplo encontra nomes iniciados por A.

Resultado
nome
Ana Costa
SELECT nome
FROM utilizador
WHERE pais_id IS NULL;

NULL requer cuidado

Use IS NULL ou IS NOT NULL. A expressão = NULL não funciona como uma comparação normal.

Resultado
nome
Eva Rocha

Teste rápido

Utilizadores ativos com reputação entre 50 e 80, inclusive.

SELECT * FROM utilizador WHERE estado = 'ativo' AND reputacao BETWEEN 50 AND 80;
04

Ordenar o resultado

ORDER BY ordena as linhas. ASC é crescente e DESC é decrescente.

SELECT nome, reputacao
FROM utilizador
ORDER BY reputacao DESC,
         nome ASC;

Mais do que um critério

Primeiro ordena pela reputação. Quando duas pessoas têm a mesma reputação, ordena esses nomes alfabeticamente.

Resultado
nomereputacao
Carla Sousa91
Ana Costa82
Fábio Alves74
Bruno Lima57
Eva Rocha57
Diogo Martins38
LIMIT: em MySQL, acrescente LIMIT 3 no fim para obter apenas as três primeiras linhas do resultado já ordenado.
05

Resumir dados

As funções COUNT, SUM, AVG, MIN e MAX transformam várias linhas num resultado resumido.

SELECT estado,
       COUNT(*) AS total,
       AVG(reputacao) AS media
FROM utilizador
GROUP BY estado;

Uma linha por grupo

GROUP BY estado forma um grupo para os ativos e outro para os inativos. Cada grupo produz uma linha no resultado.

Resultado
estadototalmedia
ativo561,60
inativo191,00
SELECT pais_id, COUNT(*) AS total
FROM utilizador
GROUP BY pais_id
HAVING COUNT(*) > 1;

WHERE e HAVING

WHERE filtra linhas antes de agrupar. HAVING filtra grupos depois de calcular a agregação.

Resultado
pais_idtotal
12
22
Erro frequente: ao usar GROUP BY, cada coluna simples do SELECT deve identificar o grupo. As restantes expressões devem usar funções de agregação.
06

A ordem das cláusulas

A consulta escreve-se numa ordem fixa. Pensar na ordem lógica ajuda a perceber o resultado.

1SELECT
2FROM / JOIN
3WHERE
4GROUP BY
5HAVING
6ORDER BY
Ordem lógica simplificada: o servidor começa por FROM, aplica WHERE, forma grupos, aplica HAVING, calcula o SELECT e ordena no fim.
07

Combinar tabelas

Um JOIN associa linhas através de valores correspondentes. A condição ON diz ao servidor como fazer essa associação.

UTILIZADORPK utilizador_idnomeFK pais_id
↔pais_id
PAISPK pais_idnome
SELECT u.nome,
       p.nome AS pais
FROM utilizador AS u
JOIN pais AS p
  ON p.pais_id = u.pais_id;

INNER JOIN

JOIN e INNER JOIN significam o mesmo. Só aparecem utilizadores que têm um país correspondente. Os prefixos u. e p. indicam a tabela.

Resultado
nomepais
Ana CostaPortugal
Bruno LimaBrasil
Carla SousaPortugal
Diogo MartinsEspanha
Fábio AlvesBrasil
Eva não aparece porque o seu pais_id é NULL.
SELECT u.nome,
       p.nome AS pais
FROM utilizador AS u
LEFT JOIN pais AS p
  ON p.pais_id = u.pais_id;

LEFT JOIN

Mostra todos os utilizadores, mesmo quando não têm país. Nesse caso, as colunas de pais aparecem com NULL.

Resultado
nomepais
Ana CostaPortugal
Bruno LimaBrasil
Carla SousaPortugal
Diogo MartinsEspanha
Eva RochaNULL
Fábio AlvesBrasil

Pergunta importante

Onde deve ficar a condição que liga as tabelas?

Em ON. Sem uma condição correta, pode obter combinações sem significado ou um número enorme de linhas.
08

Uma consulta dentro de outra

Uma subconsulta calcula um valor ou um conjunto de valores que a consulta exterior utiliza.

SELECT nome
FROM utilizador
WHERE pais_id IN (
  SELECT pais_id
  FROM pais
  WHERE nome IN ('Portugal', 'Brasil')
);

IN

A consulta interior devolve os identificadores dos dois países. A consulta exterior encontra os utilizadores cujo país pertence a esse conjunto.

Resultado
nome
Ana Costa
Bruno Lima
Carla Sousa
Fábio Alves
SELECT u.nome
FROM utilizador u
WHERE EXISTS (
  SELECT 1
  FROM post p
  WHERE p.utilizador_id = u.utilizador_id
);

EXISTS

Para cada utilizador, testa se existe pelo menos um post correspondente. O valor escrito no SELECT interior não interessa.

Resultado
nome
Ana Costa
Bruno Lima
Carla Sousa
Fábio Alves
SELECT nome, reputacao
FROM utilizador
WHERE reputacao >= ALL (
  SELECT reputacao
  FROM utilizador
);

ALL

A condição tem de ser verdadeira para todos os valores devolvidos. O exemplo encontra a reputação máxima, incluindo empates.

Resultado
nomereputacao
Carla Sousa91
09

Juntar resultados com UNION

UNION coloca as linhas de uma consulta por baixo das linhas de outra. As consultas precisam do mesmo número de colunas e de tipos compatíveis.

SELECT nome, 'utilizador' AS origem
FROM utilizador
UNION
SELECT nome, 'país' AS origem
FROM pais;

UNION ou UNION ALL

UNION elimina linhas duplicadas. UNION ALL mantém todas as linhas e costuma ser mais rápido.

Resultado, excerto
nomeorigem
Ana Costautilizador
Bruno Limautilizador
Portugalpaís
Brasilpaís
O resultado completo contém dez linhas: seis utilizadores e quatro países.
Não confundir: JOIN acrescenta colunas ao relacionar tabelas. UNION acrescenta linhas ao combinar resultados compatíveis.
10

Guardar o resultado

No phpMyAdmin, execute a consulta e use a opção Exportar junto ao resultado. O formato CSV abre facilmente numa folha de cálculo.

  1. Execute a consulta e confirme que as colunas e linhas estão corretas.
  2. Na zona do resultado, escolha Exportar.
  3. Escolha CSV, confirme o separador e descarregue o ficheiro.
Boa prática: dê nomes claros às colunas com AS antes de exportar. Esses nomes serão os cabeçalhos do ficheiro.
