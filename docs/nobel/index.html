01

Preparar o ficheiro

O contentor MySQL precisa de conseguir ver o ficheiro SQL. Para isso, guarde-o na pasta exemplos do ambiente Docker.

  1. Descarregue exportpremios.sql através do botão no início desta página.
  2. Localize no computador a pasta do projeto Docker que contém MysqlDocker.yml.
  3. Coloque o ficheiro em exemplos/exportpremios.sql. Não altere o nome.
Porque usamos a pasta exemplos? No ambiente fornecido, esta pasta do computador é partilhada com o contentor. Dentro do MySQL, o mesmo ficheiro fica disponível em /exemplos/exportpremios.sql.
02

Entrar no MySQL e importar

Abra o terminal do contentor MySQL no Docker Desktop. É nesse terminal que vai iniciar o cliente de linha de comandos do MySQL.

# No terminal do contentor MySQL
mysql -u root -p

O que significa?

mysql abre o cliente; -u root escolhe o utilizador root; -p pede a palavra-passe. Ao escrevê-la, os caracteres não aparecem no ecrã — é normal.

CREATE DATABASE nobel;
USE nobel;
SOURCE /exemplos/exportpremios.sql;

Três passos distintos

CREATE DATABASE cria a base de dados. USE torna-a ativa. SOURCE lê e executa todos os comandos do ficheiro, criando a tabela premios e inserindo os dados.

Atenção ao ponto e vírgula. Cada comando termina com ;. Aguarde até o SOURCE terminar e o prompt mysql> voltar a aparecer.
03

Confirmar a tabela e conhecer a estrutura

Antes de consultar dados, confirme o que foi criado e descubra os nomes e os tipos das colunas.

SHOW TABLES;

Que tabelas existem?

O resultado deve incluir uma tabela chamada premios. Se não aparecer, confirme que executou USE nobel; e que a importação terminou sem erros.

Resultado esperado
Tables_in_nobel
premios
DESCRIBE premios;

Como está organizada?

É apresentada uma linha por coluna. Field é o nome, Type é o tipo de dados, Null indica se pode faltar um valor e Key assinala chaves.

Identificação

id, firstname, surname e gender.

Vida e geografia

born, died, países, códigos e cidades de nascimento e morte.

Prémios

Grupos de colunas que começam por prizes_0_, prizes_1_ e prizes_2_.

04

Consultar os primeiros dados

SELECT escolhe o que queremos ver; FROM identifica a tabela; LIMIT impede que apareçam demasiadas linhas de uma só vez.

SELECT *
FROM premios
LIMIT 5;

Todas as colunas, cinco linhas

O asterisco (*) significa “todas as colunas”. A tabela tem muitas colunas, pelo que o resultado pode ficar demasiado largo no terminal.

SELECT *
FROM premios
LIMIT 1\G

Um registo na vertical

No cliente MySQL, \G substitui o ponto e vírgula e apresenta cada coluna numa linha. É especialmente útil quando uma tabela tem muitas colunas. Aqui limitamos o resultado a um registo para o observar com calma.

\G não faz parte da consulta SQL. É uma opção de apresentação do cliente de linha de comandos do MySQL.
05

Agora é a sua vez

A partir daqui, o guião deixa de dar imediatamente o comando. Observe a estrutura da tabela, pense na pergunta e escreva a sua própria consulta.

PRIMEIRO

prizes_0_*

Ano, categoria, parte do prémio, motivação e dados de afiliação do primeiro prémio.

SEGUNDO

prizes_1_*

O mesmo conjunto de informações para um eventual segundo prémio.

TERCEIRO

prizes_2_*

Informações de um eventual terceiro prémio. Para a maioria dos registos, estes campos são NULL.

Será que alguém tem um segundo prémio?

Qual é o comando SQL que permite descobrir quem tem informação nas colunas do segundo prémio?

SELECT id, firstname, surname,
       prizes_0_year, prizes_0_category,
       prizes_1_year, prizes_1_category
FROM premios
WHERE prizes_1_year IS NOT NULL
ORDER BY id;

Porquê esta condição?

Um ano em prizes_1_year indica que existe um segundo prémio. IS NOT NULL seleciona precisamente esses registos.

06

Quantos laureados existem?

Agora já não queremos ver cada laureado: queremos obter uma contagem. A função de agregação COUNT(*) conta as linhas da tabela e devolve um único resultado.

SELECT COUNT(*) AS total_laureados
FROM premios;

Contar todos os registos

COUNT(*) conta todas as linhas. AS total_laureados dá um nome mais claro à coluna calculada.

Resultado
total_laureados
955

Quantos laureados chegaram a um segundo prémio?

Escreva uma consulta que devolva apenas a quantidade. Depois pense numa segunda consulta: quantos chegaram a um terceiro prémio?

-- Pelo menos dois prémios
SELECT COUNT(*) AS laureados_com_2_premios
FROM premios
WHERE prizes_1_year IS NOT NULL;

Resultado: 6

Se prizes_1_year está preenchido, existe um segundo prémio. A consulta conta seis laureados nesta situação.

-- Três prémios
SELECT COUNT(*) AS laureados_com_3_premios
FROM premios
WHERE prizes_2_year IS NOT NULL;

Resultado: 1

O terceiro conjunto começa em prizes_2_. Apenas um laureado tem o ano do terceiro prémio preenchido.

“Pelo menos dois” não é igual a “exatamente dois”. Os seis incluem o laureado que também tem um terceiro prémio. Se pedíssemos exatamente dois, seria necessário acrescentar AND prizes_2_year IS NULL, e o resultado seria 5.

Preparar estatísticas por país

Para calcular estatísticas por país, temos primeiro de perceber como os países aparecem nos dados de nascimento.

FROM premios
LIMIT 10;

Alguns valores já são países atuais, mas outros combinam uma designação histórica com o país atual entre parênteses. Por exemplo, Prussia (now Germany).

Para agrupar corretamente, precisamos de uma referência comum. Criamos uma tabela pais com um código e a designação atual. A tabela premios pode conservar bornCountry como texto histórico, mas bornCountryCode deve ser uma chave estrangeira que aponta para o código da tabela pais.

A FK garante que cada código guardado em premios.bornCountryCode existe em pais.code. Assim, todas as variantes históricas associadas ao código DE, por exemplo, podem ser relacionadas com a designação atual Germany.

07.1

Separar texto com SUBSTRING_INDEX

Antes de trabalhar com os países, vejamos a função num exemplo diferente.

SELECT
  SUBSTRING_INDEX('aluno@universidade.exemplo', '@', 1)
    AS utilizador,
  SUBSTRING_INDEX('aluno@universidade.exemplo', '@', -1)
    AS dominio;

Como funciona?

SUBSTRING_INDEX(texto, separador, quantidade) corta o texto num separador. Uma quantidade positiva conserva a parte da esquerda; uma quantidade negativa conserva a parte da direita.

Resultado
utilizadordominio
alunouniversidade.exemplo

Como separar os países históricos?

Escreva um SELECT que apresente, para os valores que contêm (now ...), quatro colunas: o campo original, o país antigo, o país atual e o código atual.

Exemplo de uma linha do resultado esperado
campo_originalpais_antigopais_atualcodigo_atual
Prussia (now Germany)PrussiaGermanyDE
SELECT
  bornCountry AS campo_original,
  TRIM(SUBSTRING_INDEX(bornCountry, ' (now ', 1))
    AS pais_antigo,
  TRIM(TRAILING ')' FROM
    SUBSTRING_INDEX(bornCountry, ' (now ', -1))
  ) AS pais_atual,
  bornCountryCode AS codigo_atual
FROM premios
WHERE bornCountry LIKE '% (now %'
LIMIT 10;

Leitura da expressão: a primeira chamada fica com o que está à esquerda de (now . A segunda fica com o que está à direita; TRIM(TRAILING ')' ...) retira o parêntese final. O WHERE limita a consulta às linhas que têm este formato.
07.2

Criar e preencher a tabela pais

A estrutura fica definida pelo docente. O desafio é escrever o comando que obtém os países atuais a partir de premios e os insere na nova tabela.

CREATE TABLE pais (
  code VARCHAR(10) PRIMARY KEY,
  designacao_atual VARCHAR(200) NOT NULL
);

Porque é esta a estrutura?

code identifica cada país e, por ser chave primária, não aceita repetições. designacao_atual guarda o nome atual que será usado nos resultados estatísticos.

Preencha a tabela pais

Escreva um único comando INSERT ... SELECT que leia os dados de premios e insira em pais uma única linha por código, com a respetiva designação atual.

  1. Ignore linhas sem código ou sem país de nascimento.
  2. Quando existir (now ...), use o país que aparece dentro dos parênteses.
  3. Nos restantes casos, use a designação de bornCountry.
  4. Garanta que não tenta inserir várias linhas com o mesmo código.
Teste e investigue. Um primeiro comando aparentemente correto pode revelar que alguns códigos estão associados a designações diferentes. Em particular, observe os códigos GB e DK. A chave primária ajuda a descobrir este problema de qualidade dos dados.

Verificação: no fim, execute SELECT * FROM pais ORDER BY code; e confirme que cada código aparece apenas uma vez.
