Uma regra antes de alterar

O WHERE de um UPDATE ou DELETE escolhe linhas da mesma forma que num SELECT. Por isso, escreva primeiro o SELECT equivalente.

1
Selecionar: execute um SELECT com o mesmo FROM, junções e WHERE.
2
Contar: confirme as linhas e compare a quantidade com aquilo que esperava.
3
Alterar numa transação: execute a instrução e volte a consultar os dados.
4
Decidir: use COMMIT para confirmar ou ROLLBACK para desfazer.
Sem WHERE significa todas as linhas. UPDATE utilizador SET estado='inativo'; altera todos os utilizadores. DELETE FROM utilizador; tenta apagar todos os utilizadores.
01

INSERT acrescenta linhas

O destino é sempre uma tabela. Os valores podem ser escritos diretamente, linha a linha, ou resultar de uma consulta SELECT.

Uma linha

INSERT INTO pais
  (pais_id, nome)
VALUES
  (5, 'Cabo Verde');

Colunas e valores correspondem pela posição

5 entra em pais_id; 'Cabo Verde' entra em nome.

Escrever os nomes das colunas torna a instrução mais clara e protege-a de alterações na ordem física da tabela.

Linha acrescentada
pais_id nome
5 Cabo Verde

Várias linhas no mesmo comando

INSERT INTO pais (pais_id, nome)
VALUES
  (6, 'França'),
  (7, 'Itália'),
  (8, 'Alemanha');

Uma lista de linhas

Cada par de parênteses representa uma linha. Todas as linhas têm de fornecer valores compatíveis com a mesma lista de colunas.

Resultado
O MySQL indica 3 rows affected.

Uma linha de cada vez a partir de dados externos

Não confundir SQL com o ciclo da aplicação. Um programa pode percorrer um ficheiro e executar um INSERT por linha. Funciona, mas costuma implicar muitas comunicações com o servidor. Quando possível, envie várias linhas no mesmo INSERT, use importação de CSV ou carregamento em lote.

INSERT como resultado de um SELECT

CREATE TABLE autores_destaque (
  utilizador_id INT PRIMARY KEY,
  nome VARCHAR(80) NOT NULL,
  total_gostos INT NOT NULL
);

INSERT INTO autores_destaque
  (utilizador_id, nome, total_gostos)
SELECT u.utilizador_id, u.nome,
       SUM(p.gostos)
FROM utilizador AS u
JOIN post AS p
  ON p.utilizador_id = u.utilizador_id
GROUP BY u.utilizador_id, u.nome
HAVING SUM(p.gostos) >= 20;

O SELECT produz as novas linhas

Não existe VALUES. Cada linha devolvida pelo SELECT é inserida em autores_destaque.

O número, a ordem e os tipos das expressões selecionadas têm de ser compatíveis com as colunas de destino.

Linhas inseridas
utilizador_id nome total_gostos
101 Ana Costa 20
102 Bruno Lima 21
106 Fábio Alves 26
Regras continuam ativas: PK, UNIQUE, FK, NOT NULL e CHECK são verificadas em cada linha inserida. Se uma linha violar uma restrição, a instrução pode falhar.
02

UPDATE altera linhas existentes

SET define os novos valores. WHERE decide que linhas os recebem. A expressão da direita pode usar os valores antigos da própria linha.

-- Ver primeiro
SELECT utilizador_id, nome, reputacao
FROM utilizador
WHERE estado = 'ativo'
  AND reputacao < 60;

-- Alterar depois
UPDATE utilizador
SET reputacao = reputacao + 5
WHERE estado = 'ativo'
  AND reputacao < 60;

O novo valor depende do antigo

reputacao + 5 é calculado separadamente para cada linha escolhida.

Podemos alterar várias colunas separando atribuições por vírgulas: SET estado='ativo', reputacao=0.

Antes e depois
nome antes depois
Bruno Lima 57 62
Diogo Martins 38 43
Eva Rocha 57 62

UPDATE que consulta outra tabela

-- Pré-visualização
SELECT u.nome, u.reputacao,
       SUM(p.gostos) AS gostos
FROM utilizador AS u
JOIN post AS p
  ON p.utilizador_id = u.utilizador_id
GROUP BY u.utilizador_id, u.nome, u.reputacao
HAVING SUM(p.gostos) >= 20;

UPDATE utilizador AS u
JOIN (
  SELECT utilizador_id
  FROM post
  GROUP BY utilizador_id
  HAVING SUM(gostos) >= 20
) AS elegivel
  ON elegivel.utilizador_id = u.utilizador_id
SET u.reputacao = LEAST(100, u.reputacao + 10);

Primeiro calcular; depois ligar

A subconsulta agregada produz os identificadores elegíveis. O JOIN liga-os às linhas que serão atualizadas.

LEAST(100,...) impede ultrapassar 100. A junção escolhe linhas; o único alvo alterado continua a ser u.

Linhas elegíveis
Ana, Bruno e Fábio têm pelo menos 20 gostos acumulados.
03

DELETE remove linhas

DELETE remove linhas inteiras. Não existe “apagar só uma coluna”; para retirar o seu valor usa-se normalmente UPDATE ... SET coluna = NULL, se a coluna aceitar NULL.

-- Ver exatamente o que será removido
SELECT *
FROM post
WHERE publicado_em < '2026-03-05';

DELETE FROM post
WHERE publicado_em < '2026-03-05';

A tabela vem depois de DELETE FROM

O exemplo remove posts antigos. O WHERE pode conter as mesmas condições, complexas de um SELECT.

A operação não renumera PKs e não deve reutilizar identificadores apenas porque uma linha foi apagada.

Linha removida
O post 1001, publicado em 2 de março, satisfaz a condição.

A chave estrangeira pode impedir o DELETE

DELETE FROM utilizador
WHERE utilizador_id = 101;

Ana ainda tem posts

Se post.utilizador_id referencia Ana com a ação normal RESTRICT/NO ACTION, o SGBD recusa apagar a linha.

As alternativas dependem do requisito: impedir, apagar primeiro os posts, usar ON DELETE CASCADE, ou permitir SET NULL quando posts anónimos fizerem sentido.

Operação recusada
Não se pode deixar uma FK a apontar para uma linha que deixou de existir.
TRUNCATE TABLE não é simplesmente um DELETE mais curto. Remove todas as linhas, não aceita WHERE, tem comportamento próprio de DDL e pode reiniciar o contador AUTO_INCREMENT. Use-o apenas quando pretende esvaziar integralmente a tabela.
04

Uma ou várias tabelas?

Uma consulta pode usar muitas tabelas para decidir as linhas. Isso não significa automaticamente que todas serão alteradas. O alvo da operação tem de estar explícito.

UPDATE de uma tabela

UPDATE utilizador u JOIN post p ... SET u.estado=... consulta ambas, mas só altera u.

DELETE de uma tabela

DELETE u FROM utilizador u JOIN ... usa a junção, mas a lista depois de DELETE contém apenas u.

Vários alvos no MySQL

O MySQL permite indicar vários aliases como alvos. É uma extensão poderosa e muito mais arriscada.

UPDATE de duas tabelas numa instrução MySQL

UPDATE utilizador AS u
JOIN post AS p
  ON p.utilizador_id = u.utilizador_id
SET u.reputacao = u.reputacao + 1,
    p.gostos = p.gostos + 1
WHERE p.post_id = 1003;

Dois alvos, uma condição

Esta sintaxe específica do MySQL altera uma coluna de utilizador e outra de post.

Numa atualização multi-tabela, o MySQL não permite ORDER BY nem LIMIT. A ordem em que as tabelas são processadas não deve ser usada como parte da lógica.

Alterações
Bruno recebe +1 de reputação e o post 1003 recebe +1 gosto.

DELETE com uma junção: escolher o alvo

-- Apagar apenas posts de utilizadores inativos
DELETE p
FROM post AS p
JOIN utilizador AS u
  ON u.utilizador_id = p.utilizador_id
WHERE u.estado = 'inativo';

-- MySQL permite dois alvos:
DELETE p, u
FROM utilizador AS u
JOIN post AS p
  ON p.utilizador_id = u.utilizador_id
WHERE u.utilizador_id = 103;

A lista após DELETE é decisiva

DELETE p remove apenas linhas de post. DELETE p, u pede para remover linhas das duas tabelas.

As FKs continuam a ser verificadas. Uma operação com vários alvos pode falhar se a ordem escolhida pelo otimizador entrar em conflito com a integridade referencial. Muitas vezes, ON DELETE CASCADE ou duas instruções explícitas numa transação são mais previsíveis.

Limitações importantes
O DELETE multi-tabela do MySQL também não aceita ORDER BY nem LIMIT. Não existe uma sintaxe multi-tabela portável igual em todos os SGBD.
Regra de clareza: use outras tabelas para localizar as linhas quando necessário, mas altere o menor número possível de tabelas por instrução. Se a regra de negócio envolve várias alterações relacionadas, use uma transação.
05

Transações e verificações

Uma transação permite observar o resultado antes de o tornar definitivo. Também garante que um conjunto de operações fica completo ou não fica aplicado.

START TRANSACTION;

UPDATE utilizador
SET reputacao = reputacao + 5
WHERE utilizador_id = 102;

SELECT * FROM utilizador
WHERE utilizador_id = 102;

ROLLBACK; -- desfazer
-- ou COMMIT; para confirmar

Enquanto não houver COMMIT

A própria sessão vê a alteração. Outras sessões dependem do nível de isolamento. ROLLBACK repõe o estado anterior.

Tabelas InnoDB suportam transações. Algumas instruções DDL podem provocar confirmação implícita; não suponha que qualquer comando pode ser desfeito.

Verificações úteis
SELECT ROW_COUNT(); devolve o número de linhas afetadas pela instrução anterior. Confirme também valores antes e depois.
Rotina segura: faça backup quando o impacto for grande; teste primeiro num ambiente não produtivo; execute o SELECT equivalente; abra uma transação; altere; valide contagens e amostras; só então faça COMMIT.

Exercícios

Escreva sempre a consulta de pré-visualização antes da instrução que altera dados.

Inserção controlada

Insira Angola e Moçambique numa tabela nova chamada pais_lusofono, copiando apenas países já existentes em pais. A solução tem de usar INSERT ... SELECT, não pode repetir nomes em VALUES.

Clonar sem repetir PK

Crie post_arquivo com a mesma estrutura lógica de post. Copie para lá posts anteriores a 10 de março que ainda não estejam no arquivo. A instrução deve poder ser executada duas vezes sem duplicar linhas e sem usar INSERT IGNORE.

Atualização com CASE

Numa única instrução, aumente 10 pontos aos utilizadores com reputação abaixo de 50, 5 pontos aos que estão entre 50 e 79, e não altere os restantes. Nenhuma reputação pode ultrapassar 100.

UPDATE difícil: desempenho relativo ao país

Aumente 7 pontos de reputação apenas aos utilizadores cuja reputação seja inferior à média do próprio país, excluindo quem não tem país. Resolva com uma subconsulta agregada ligada ao UPDATE. Garanta o máximo de 100.

UPDATE difícil: prémio proporcional aos posts

Para cada autor, some os gostos dos posts publicados em março. Aumente a reputação em 10% desse total, arredondado para baixo, mas apenas se existirem pelo menos dois posts. A reputação final não pode ultrapassar 100. Faça tudo num único UPDATE.

UPDATE com o máximo do grupo

Marque como inativo todo o utilizador cuja reputação esteja pelo menos 30 pontos abaixo da maior reputação do seu país. Não altere utilizadores sem país nem países com apenas um utilizador.

Apagar com dependências

Apague utilizadores inativos que não tenham qualquer post. Primeiro resolva com NOT EXISTS. Explique por que razão a operação não viola a FK e compare-a com tentar apagar todos os inativos.

Arquivar e apagar atomicamente

Copie para post_arquivo os posts anteriores a uma data e, apenas se a cópia tiver sucesso, apague-os de post. Mostre a transação completa e uma verificação que compare quantidades antes do COMMIT.

Dois alvos, ou duas instruções?

Ao eliminar um utilizador escolhido, pretende apagar também os seus posts. Escreva uma solução MySQL com DELETE p,u e outra com duas instruções numa transação. Discuta qual é mais clara e como ON DELETE CASCADE mudaria a solução.

Antes de executar

Que linhas?

Confirme-as com SELECT.

Que tabelas?

Distinga tabelas consultadas de alvos alterados.

Que restrições?

Antecipe PK, UNIQUE, FK, NOT NULL e CHECK.

Como desfazer?

Use transação, validação e backup adequado.
