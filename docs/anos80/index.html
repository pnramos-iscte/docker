01

Retomar a base de dados no Docker

A base imdb já deve estar importada. Inicie os contentores, abra o cliente MySQL e confirme as três tabelas necessárias.

  1. Abra um terminal na pasta onde guardou MysqlDocker.yml.
  2. Inicie os contentores.
  3. No Docker Desktop, abra o terminal do contentor MySQL através da opção ….
  4. Entre no cliente MySQL, ative imdb e confirme as tabelas.
# Terminal na pasta do Docker
docker compose -f MysqlDocker.yml up -d

# Terminal do contentor MySQL
mysql -u root -p
USE imdb;
SHOW TABLES;

DESCRIBE titlebasics;
DESCRIBE namebasics;
DESCRIBE titleprincipals;
Não altere já a estrutura. Primeiro execute a consulta sem novos índices e registe o tempo. Sem uma medição inicial não existe comparação.

04

Quantas vezes Woody Allen representa a si próprio?

Agora atravessamos namebasics e titleprincipals. O campo characters deve ser exatamente ['Himself'].

1. Construa a consulta de contagem

Ligue as tabelas através de nconst, filtre primaryName = 'Woody Allen' e conte as participações em que o personagem é ele próprio.

Antes da otimização33,11 s

A consulta encontra a resposta, mas demora demasiado tempo.

Depois da otimização0,49 s

A mesma resposta foi obtida cerca de 68 vezes mais depressa.

EXPLAIN
SELECT *
FROM namebasics
WHERE primaryName = 'Woody Allen';

O que faz o EXPLAIN?

EXPLAIN não executa a consulta para apresentar os dados. Mostra o plano que o MySQL pretende usar para os encontrar.

table identifica a tabela; type indica a forma de acesso; key mostra o índice escolhido, ou NULL se não escolher nenhum; rows estima quantas linhas terá de examinar.

Os valores concretos dependem dos índices existentes na sua base de dados.

2. Descubra o índice que falta

Qual é o campo usado para procurar, dentro de titleprincipals, todas as participações da pessoa encontrada em namebasics? Crie o índice e volte a medir.

Uma FK não é apenas uma seta num desenho. É o campo usado para chegar às linhas relacionadas. Nesta cópia dos dados IMDb, confirme sempre com SHOW INDEX se esse campo está efetivamente indexado.

06

Restaurar e concluir

Um ensaio de desempenho deve terminar deixando a base no estado inicial.

Remova apenas os índices criados neste exercício

Não elimine índices que já existiam antes. Use SHOW INDEX FROM nome_tabela; para confirmar os nomes.

1. Correção

Leia literalmente o enunciado e teste casos-limite, incluindo valores NULL.

2. Evidência

Compare tempos da mesma consulta, com os mesmos dados e no mesmo computador.

3. Explicação

Use EXPLAIN e SHOW INDEX; não conclua apenas pelo cronómetro.

O método que deve ficar

Compreender a pergunta → validar o SQL → medir → observar o plano → criar um índice coerente com filtros e ligações → voltar a medir → restaurar.
