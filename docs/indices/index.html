01

O que é um índice?

Um índice é uma estrutura auxiliar que guarda valores de uma ou mais colunas numa ordem que facilita a localização das linhas. Em MySQL, muitos índices usam uma árvore B. A tabela continua a guardar os dados; o índice guarda chaves e referências para chegar às linhas.

Sem índice

O motor pode percorrer a tabela linha a linha até encontrar os registos.

type: ALL
rows: 1 000 000

Com índice adequado

O motor percorre a árvore e visita apenas a zona onde podem estar os valores.

type: ref
rows: 240

O preço da velocidade

Os índices ocupam disco e memória. Cada INSERT, alteração da coluna indexada ou DELETE também atualiza o índice. Por isso, um índice pode acelerar leituras e tornar escritas mais lentas.

Exemplo mostrado nos slides fornecidosPesquisa sem índice: cerca de 10,2 sA mesma pesquisa após criar o índice: cerca de 0,04 s
02

Que coluna deve ser indexada?

Comece pelas consultas reais, sobretudo pelas colunas usadas frequentemente em WHERE, JOIN e, nalguns casos, ORDER BY. Uma coluna com muitos valores distintos costuma permitir eliminar mais linhas do que uma coluna com dois valores.

Bom candidato

Código de aeroporto, email, data combinada com outra condição ou uma FK usada em junções.

Candidato fraco isoladamente

Um booleano ou uma coluna em que quase todas as linhas têm o mesmo valor.

Índice composto

(ORIGIN_AIRPORT, DESTINATION_AIRPORT) ajuda a procurar uma rota.

Regra da esquerda

Esse índice também pode ajudar a procurar pela origem, mas normalmente não pela coluna de destino isolada.

CREATE INDEX ix_nome
ON nomes (primaryName);

CREATE INDEX ix_rota
ON flights (ORIGIN_AIRPORT, DESTINATION_AIRPORT);

DROP INDEX ix_rota ON flights;

Primeiro corrija os dados

Nesta base, alguns códigos de destino terminam em \r. Isso explica resultados estranhos de LENGTH(). Aplicar TRIM() resolve a consulta pontualmente, mas pode impedir uma pesquisa direta pelo índice. É preferível limpar e normalizar os dados.

UPDATE flights
SET DESTINATION_AIRPORT = TRIM(DESTINATION_AIRPORT),
    ORIGIN_AIRPORT = TRIM(ORIGIN_AIRPORT);
03

O MySQL decide se usa o índice

Criar um índice não obriga o otimizador a utilizá-lo. O MySQL estima o custo de vários planos e pode concluir que ler a tabela inteira é mais rápido, sobretudo quando a consulta devolve grande parte das linhas.

EXPLAIN
SELECT *
FROM flights
WHERE ORIGIN_AIRPORT = 'ALB'
  AND DESTINATION_AIRPORT = 'ATL';
typeALL indica varrimento completo; ref ou range costumam indicar pesquisa mais seletiva.possible_keysÍndices que poderiam ajudar.keyÍndice efetivamente escolhido.rowsNúmero estimado de linhas a examinar.ExtraInformação adicional, como filtros ou ordenação temporária.

Compare sempre o mesmo comando, com os mesmos dados, antes e depois. O tempo isolado pode variar devido à cache. Use também EXPLAIN ANALYZE quando a versão do MySQL o suportar.
